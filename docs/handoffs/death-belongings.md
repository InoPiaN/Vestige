# 사망 현장 유품과 회수 · 0.4.4

Codex · 2026-11-09 · `feat/death-belongings` · 기준 `92b8280`.

`death_belongings.gd`가 `w.remains[life]`에 name/x/y/day/contents를 저장한다. world.die에서 장비 상태를 정리한 뒤 사망 캐릭터의 일반 물품과 은화를 빈 유품 컨테이너로 이전하고, 캐릭터의 수량·장비 ID·착용 상태·은화를 비운다. 사건 증거는 기존 별도 drop을 유지하고 집 storage는 건드리지 않는다. 재사망 호출은 기존 alive 검사와 life 키로 멱등 처리한다. 자연사/오프라인 경과도 같은 경로다.

`take_remains`의 값은 `life|item_id`. 서버가 생존·직접 조종·2타일 미만 거리·수량·개별 장비 ID·소지 한도를 검사한다. 1개 단위 이동이며 은화도 1개씩 회수한다. 회수 장비는 자동 착용하지 않는다. 반복 요청/경쟁 회수로 ID가 복제되지 않는다. 유품은 가까운 경우에만 snapshot에 포함한다. 완전히 빈 컨테이너는 재생성 방지를 위해 저장에는 남고 발견 목록과 흔적 표시에서는 제외한다.

기존 storage_panel.gd를 유품 모드로 재사용한다. G는 유품, B는 집이며 single에서 둘 다 일시정지한다. 주변의 여러 유품은 OptionButton으로 고른다. 선택 변경은 일시정지 상태에서도 즉시 갱신한다. Claude 통합은 main.gd의 G 처리와 storage_panel의 remains_mode, Items의 개별 장비 정의를 유지할 것. 이번 시작 시 새 Claude 원격 변경은 없었다.

저장 형식 5. 버전 1~4를 이관하며 과거 사망에 유품을 재구성하지 않는다. house_storage.valid는 캐릭터·집·유품 전체에서 장비 ID의 중복과 수량 일치를 확인한다. 사용자 월드는 테스트에 사용/초기화하지 않았다. 오래된 customization 회귀 테스트가 이전 임시 파일을 읽을 수 있던 문제도 수정: 실제 버전 1 fixture를 직접 기록한 뒤 로드한다.

체험: `-- --remains-demo` 또는 builds/Play-Remains.command. 저장은 독립 user://remains-demo.json이며 재실행 시 그대로 이어간다. 새 캐릭터가 장터 동쪽 유품 가까이에서 시작한다. 여행자가 집에 약초를 남기고 검을 제작한 뒤 사고로 사망한 초기 시나리오다. 예전 witness/investigation 실행기도 0.4.4를 가리킨다.

검증: 신규 24개 포함 152개 검사, 첫 여정 30/60Hz, 실제 ENet 현장 접근→검 회수→같은 요청 반복에서도 하나만 유지. 서버 접속 대기 중 NPC 생활 이동을 반영해 네트워크 시험은 현장까지 실제 이동한다. 임시 서버 종료. scripts/render_remains.gd로 유품 화면 렌더링 및 육안 확인. Mac 서명/headless 메뉴 기동, Windows export/PE 확인. Windows 실기 미검증. 저장 실패 시험의 의도된 오류와 샌드박스 macOS 인증서 경고 외 스크립트 오류 없음.

남은 범위: 여러 주택·건설·상속, 장비 내구도/강화/품질, 유품 소유권·절도·보존 기간·부활 반환 규칙. 현재 유품은 누구나 회수하며 만료하지 않는다. 새 캐릭터의 시작 장비와 은화는 기존 정책대로 별도로 지급된다. 따라서 경제 밸런스와 반복 생애 시작 보상 정책도 출시 전 조정이 필요하다. 다중 저장 작성자/Steam Cloud 충돌, 서버 저장 간격 내 장애 복구도 별도다. 누적 기능 브랜치는 아직 main에 병합하지 않았다.
