# 잿불 마을 첫 플레이 가능 스토리 슬라이스 — 구현 계획

상태: 구현 계획 (코드 미구현). 기준: `feature/ai-mcp-asset-pipeline`에서 분기. 스토리 초안은 별도 `docs/vestige-story-concept-v0-3` 브랜치의 `docs/STORY_CONCEPT.md` 참고. **사건의 진실은 아직 가설**이며 확정하지 않는다.

## 기존 코드에서 확인한 기반

- `desktop/main.gd`: 싱글/멀티 플레이, WASD 이동, E 상호작용, I 인벤토리, J 일지, 저장/불러오기, 패널 UI
- `desktop/world.gd`: `PLACES` 시설 좌표, `nearby()`, `act()`, `fresh()/born()/load_world()/save_world()`, 기존 채집·제작·전투 루프
- 기존 `library`와 `grave`는 `main.gd`에서 전용 UI를 열고, 나머지는 `act(...,"interact")`로 처리
- `desktop/inventory_panel.gd`: PNG가 없을 때 절차적 아이콘 사용. 이번 작업에서 이미지 생성 금지

## 첫 목표: 대화가 가능한 잿불 마을

1. NPC 브란(대장간), 세라(서재)를 **기존 시설과 충돌하지 않는** 상호작용 대상으로 추가. 카엘은 첫 단계에서 등장 여부를 스토리 플래그로 관리하며 사건의 진실을 확정하는 대사는 금지.
2. `E` 키로 주변 NPC를 선택하여 대화 패널을 연다. NPC가 없으면 기존 시설 상호작용이 이전과 동일하게 동작한다.
3. 최소 대사 분기: 최초 대화 / 재방문 / 이렌 실종 소문 확인. 플레이어가 소문을 듣지 않아도 기존 채집·단조 루프를 계속할 수 있다.
4. 대화 상태는 **플레이어별**로 저장하고 로드한다. 기존 `version:1` 저장 파일은 기본값 보충으로 계속 읽을 수 있어야 한다.
5. 멀티플레이에서는 클라이언트가 임의로 월드 상태를 덮어쓰지 못하도록 기존 서버 권위 경로를 따른다. 첫 슬라이스가 싱글 전용이면 UI에서 명시하고 서버 기능을 깨뜨리지 않는다.
6. 임시 도형·텍스트로 표현하며 아트 파일이나 API 생성 기능을 호출하지 않는다.

## 구현 우선순위

- **A. 이동 및 접근:** 기존 WASD/충돌/카메라 유지, NPC 상호작용 거리 명확화
- **B. 대화 데이터:** NPC ID, 위치, 조건, 대사, 선택지와 결과를 데이터로 분리
- **C. 대화 UI:** 기존 패널과 키 입력 충돌 방지, 닫기/재진입 지원
- **D. 조사 상태:** 소문 청취 플래그, 대화 이력 및 일지 갱신
- **E. 후속 작업:** 이렌의 집·예배당 증거·카엘 대면·공개/보존/증언 선택. 이 단계에서 무리하게 구현하지 않음

## 완료 조건

- 새 싱글 세이브로 이동→브란 대화→세라 대화→소문 확인→일지 확인→저장→재시작 후 상태 유지
- NPC를 무시하고 광석 채집→검 제작이 정상 동작
- 대화 중 이동/공격/인벤토리 입력 충돌 없음
- NPC가 멀리 있으면 대화가 열리지 않음
- 기존 세이브 로드, 사망 후 새 인물, 멀티 서버 시작에 회귀 오류 없음
- Godot 4.5.x 헤드리스 파싱/테스트와 실제 UI 수동 검증을 구분해 기록

## 구현 범위 밖

AI 이미지 생성, API 과금, 최종 그래픽, 사건 범인 확정, 완성형 퀘스트 시스템, 모든 NPC·맵 제작.
