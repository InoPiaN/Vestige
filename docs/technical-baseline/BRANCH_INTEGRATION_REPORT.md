## 권장 통합 순서 및 안전 절차
1. 사용자에게 본 보고서의 G 기반 통합/저장 정책을 승인받고 목적별 codex/feature 브랜치를 만든다. main 직접 수정 금지.
2. 기준 SHA와 diff, 사용자 변경/스태시 ID를 기록한다. 양쪽 테스트를 독립 실행한 상태를 출발점으로 고정한다.
3. S의 story 규칙·대화·증거/테스트를 별도 이름으로 이식한다. 자산 MCP 전체 이력은 별도 범위로 다룬다.
4. 지역 검증·죽음/새 생애 초기화·수첩·E 우선순위를 먼저 연결한다. 기존 집/전투/제작/이동은 유지한다.
5. 승인을 받은 저장 계약 아래 검증기/이관과 실패 복구를 구현한다. v1 story fixture와 v23 gameplay fixture를 각각 지원하고 자동으로 두 실제 월드를 합치지 않는다.
6. 서버 세션·snapshot·재구성 명령을 연결한다. 미보유/타인/사망/부재/다른 지역/재전송·재접속 검사를 추가한다.
7. 양쪽 기존 회귀+실제 두 클라이언트 조합/재시작+실제 UI·조작 검증. G 기능이 하나라도 사라지면 통합 완료로 표시하지 않는다.
8. 검증된 통합 브랜치와 리뷰 가능한 커밋을 제공한다. main 병합·배포는 별도 승인이다. 새 패키지 검증 이전에는 기존 정상 실행본을 삭제하지 않는다.

이번 승인 범위는 분석/문서화이다. 사용자가 지정한 향후 1단계 “통합·안정화”를 이번 즉시 전체 병합 허가로 확대 해석하지 않는다.
