# Git 작업 방식

## 첫 기준점

0.3.1 시제품을 첫 커밋으로 기록한다. 이전 대화의 각 작업을 실제 과거 커밋으로 재구성하지 않는다. 이전 결정과 진행 기록은 기획서, 개발 목록, 인계 문서에 남아 있다.

## 기록할 파일

게임 소스, 테스트, 기획서, README, 빌드/검증 스크립트, Godot 리소스 UID, 소규모 아트 검토 이미지. 대규모 아트 원본은 필요해질 때 Git LFS 도입을 검토한다.

## 제외할 파일

사용자 저장(data/), 실행 파일(builds/), 다운로드 엔진/템플릿(.tools/), Godot 캐시, 자격 증명, 로그와 임시 파일. 실행 파일 배포는 향후 릴리스 첨부 파일로 분리한다.

## 이후 진행

1. 기능별 브랜치에서 코드와 관련 기획을 함께 변경한다.
2. 해당 기능 검사와 필요한 회귀 검사를 실행한다.
3. 무엇이 달라졌는지 설명하는 작은 단위의 커밋을 만든다.
4. 구현 완료/미완료 상태를 개발 목록에 반영한다.
5. 원격 연결 후 사용자 지정 저장소로 푸시한다. 공개 전환과 Steam 게시는 별도 결정한다.

기본 브랜치는 `main`이다. 2026-11-06에 GitHub에서 `InoPiaN/Vestige`의 공개 상태를 확인했다.

## Claude와 Codex가 함께 작업할 때

- 각 도구는 작업 시작 시 `git fetch origin`, `git status --short --branch`, 최근 커밋과 인계 메모를 확인한다. 동시에 작업할 때는 기능별 브랜치와 별도 작업 폴더(worktree)를 사용한다. 같은 폴더에서 브랜치를 바꾸면 상대 작업에도 영향을 준다.
- 완료한 쪽은 기능 브랜치를 푸시하고, 커밋 또는 PR 본문에 변경 범위, 검증 결과, 남은 작업을 남긴다. 파일로 남길 때는 `docs/handoffs/기능명.md`를 권장한다. 이미 작성한 인계 파일이 있으면 그 경로를 공유해도 된다.
- 다음 작업자는 해당 브랜치와 `main`의 차이를 확인한 뒤 관련 기능을 이어간다. 채팅 사이에 자동으로 완료 알림이 전달되지는 않는다.
