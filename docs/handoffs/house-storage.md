# 집 보관함과 개별 장비 · 0.4.3

Codex · 2026-11-09 · `feat/house-storage` · 기준 `8cb40de`.

`house_storage.gd`는 집 보관함의 접근·용량·이동 규칙과 개별 장비 ID를 관리한다. B로 `storage_panel.gd`를 열어 물품 1개씩 보관·회수한다. 전체 보관 수량은 40개. 회수는 소지품 종류별 기존 한도를 따른다. 살아 있는 소유자의 집은 소유자만, 사망한 소유자의 집은 가까이 온 인물이 이용한다. 소유권 상속은 아직 아니다. 증거물은 기존 별도 I/F 흐름이다.

장비 `gear_instances`는 ID→종류, `equipped_ids`는 슬롯→ID이다. 기존 `equipment` 종류는 렌더링·전투와 호환하도록 유지한다. 기존 종류별 수량이 생산/채집 코드의 기준이며 `reconcile`이 수량에 맞춰 ID를 부여한다. 종류가 같은 장비의 ID를 임의로 교체하지 말 것. 보관함 이동은 정확한 ID를 이전한 뒤 수량을 조정한다. 제작/로드/저장/장비 변경 시 일치시킨다. 향후 개별 장비 속성을 넣을 때는 개별 레코드 중심으로 생산 코드를 전환하는 것이 다음 단계다.

저장 형식 4. 버전 1·2·3 로드 시 기존 물품에 ID와 빈 보관함을 추가한다. 이후 구버전 앱은 이 저장을 열지 않는다. duplicate ID/수량 불일치/유효하지 않은 착용 참조를 검증한다. `relic_found`로 유물을 집에 넣고 원래 장소에서 다시 얻는 경로를 막았다. 사용자 월드를 테스트에 사용하거나 초기화하지 않았다.

Claude 통합 참고: 이번 시작 시 원격 신규 Claude 변경 없음. main.gd의 B 입력·보관함 생성/갱신·메시지·싱글 일시정지 처리를 추가했다. 기존 인벤토리에서 Items.definition을 유지하고 `gear-` 선택은 equip_instance 액션을 사용한다. 스타일 변경은 최소화했다. 원격 snapshot은 접근 가능한 가까운 인물에게만 보관함을 보내며 타인 개별 장비 ID는 제외한다.

검증: 신규 22개 포함 총 128개 검사, 첫 여정 30/60Hz, 실제 ENet 서버에서 같은 장비 ID의 보관·회수 통과. /tmp 임시 월드와 서버 사용 후 종료. scripts/render_storage.gd로 보관함과 개별 장비 화면을 렌더링하고 육안 확인. Mac·Windows 빌드는 builds의 0.4.3 경로다. Mac ad-hoc 서명 및 headless 메뉴 기동, Windows PE 형식 확인을 마쳤다. Windows 실기 검증은 미실시.

한계/다음: 일반 소지품은 아직 사망 장소에 유품으로 남지 않는다. 집 보관물만 후대에 보존한다. 일반 사망 유품화·회수, 내구도/강화/품질, 여러 주택·건설·상속, 다중 저장 작성자/Steam Cloud 충돌, Claude UI 통합이 남아 있다. 기능 브랜치들은 아직 main에 병합하지 않았으므로 이 브랜치가 최신 누적 기준이다.
