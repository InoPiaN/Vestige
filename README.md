# Vestige · 설치형 도트 시제품 0.4.3

## 바로 실행

- Mac 최신: `builds/Vestige-0.4.3.app`을 엽니다. Node.js나 Godot를 별도로 실행할 필요가 없습니다.
- Windows 최신: `builds/windows-0.4.3/Vestige.exe`를 실행합니다. Windows 빌드는 생성했지만 현재 Mac 개발 환경에서는 Windows 실행을 검증하지 않았습니다.
- 설치형 소스: `desktop/project.godot` (Godot 4.5.1로 빌드·검증).

현재 Mac 앱은 로컬 시험용 ad-hoc 서명 빌드이며 공증된 배포본이 아닙니다. Steam 연동은 아직 없습니다.

### 장터의 마지막 장부 (목격자 체험)

Mac은 빌드 폴더의 **Play-Witness.command**, Windows는 **Play-Witness.cmd**로 엽니다. 실행 파일에 `-- --witness-demo`를 전달해도 됩니다. 조사 상태는 `witness-demo.json`에 저장됩니다.

묘지에서 F로 장부지기 은결의 기록을 살핀 후, 언덕집 장부와 장터 동쪽의 현장 조각을 조사합니다. 장터 상자 옆 등불지기 미라에게 다가가 F로 말을 걸면 그날 직접 본 모습이 수첩에 남습니다. J로 단서를 비교하고 묘지에서 F를 누른 뒤 숫자 1 또는 2로 용의자를 지목합니다. 잘못 지목해도 기록을 재검토하고 다시 선택할 수 있습니다.

현장에서 F를 누르면 고리 조각이 소지품에 들어옵니다. 집 문 앞에서 I → 고리 조각 → **집 보관함에 남기기**를 선택하세요. 이후 F로 회수할 수 있고 다른 캐릭터도 발견할 수 있습니다. 소지자가 죽으면 조각은 그 사망 장소에 남습니다. 수첩의 관찰 기록은 물건을 보관해도 유지되며, 다음 캐릭터에게 자동 승계되지 않습니다. 증거물은 사건 한 건을 지원하며, 일반 물품은 아래 집 보관함을 이용합니다.

### 소율의 마지막 행적 (체험 월드)

프로젝트 루트에서 다음 명령으로 독립 싱글 저장 `investigation-demo.json`을 열 수 있습니다. 일반 월드에서는 마을 서남쪽 언덕집 문 앞에서 E로 은화 8개에 집을 매입합니다. 이후 E를 누를 때마다 그때까지의 일지를 책장에 보관합니다.

```sh
builds/Vestige-0.4.3.app/Contents/MacOS/Vestige -- --investigation-demo
```

Windows에서는 빌드 폴더에서 `Vestige.exe -- --investigation-demo`를 실행합니다. 체험 월드는 약초꾼 소율이 예배당으로 떠난 뒤 새 여행자가 도착한 상태에서 시작합니다.

1. 서남쪽 묘지에서 F로 수습 지역을 확인합니다.
2. 묘지 동쪽 언덕집 문 앞에서 E 또는 F로 집에 보관된 일지를 읽습니다.
3. 동쪽 예배당 길목에서 흔적 가까이 다가가 F로 조사합니다. J를 누르면 발견한 내용이 조사 수첩에 남습니다.
4. 묘지로 돌아와 F를 누르면 장례 기록과 단서를 대조해 사인이 새겨집니다. 서재에서는 현장에서 회수한 마지막 메모까지 읽을 수 있습니다.

저장은 버전 4이며 버전 1·2·3 월드를 자동 이관합니다. 증거물이 있는 월드는 0.4.3 이상에서 이어서 플레이하세요. 같은 이름의 다음 인물은 별도 수첩으로 시작합니다. 체험 월드도 재실행하면 조사 진행을 이어갑니다.

### 집 보관함과 개별 장비

집 문 근처에서 **B**를 눌러 보관함을 엽니다. 왼쪽 소지품 또는 오른쪽 집 물품을 선택한 뒤 버튼으로 1개씩 옮깁니다. 보관함은 집당 총 40개 한도이며, 꺼낼 때는 기존 소지 한도(철광석·약초 20개, 철검 5개 등)를 적용합니다. 착용 중인 장비를 보관하면 벗습니다. B·ESC·닫기로 창을 닫습니다.

살아 있는 집주인은 본인만 이용할 수 있고, 사망한 주인의 집은 다른 인물도 회수할 수 있습니다. 보관물은 주인이 사망해도 남습니다. 현재 집은 한 채이며 상속 소유권 이전·건설은 아직 없습니다. 증거물은 기존 I 보관/F 회수 흐름을 유지합니다.

장비는 같은 종류라도 짧은 번호로 구분됩니다. 인벤토리에서 특정 철검을 선택해 착용하고, 집에 보관했다 꺼내도 같은 장비로 유지됩니다. 현재 장비별 성능은 동일하며 내구도·강화·품질 차이는 후속 작업입니다. 사망 시 일반 소지품을 현장 유품으로 남기는 기능은 아직 없으므로 후대에 남길 물품은 집에 보관하세요.

### 캐릭터 생성과 장비

새 싱글 월드는 생성 화면에서 이름·머리·머리색·피부·의복색을 선택합니다. 기존 저장은 그대로 이어집니다. 멀티 신규 인물은 접속 전 ‘인물 외형 선택’을 사용합니다. 사망 후 새 인물도 외형을 선택할 수 있습니다.

게임 오른쪽 ‘외형 · 장비’에서 가죽 갑옷·후드·망토·철검을 착용/해제하고 투구를 숨길 수 있습니다. 갑옷·후드·망토는 시작 외형 장비이며 방어력은 아직 없습니다. 철검은 제작 후 착용할 수 있고 착용할 때만 공격력 22가 적용됩니다(맨손 9). 기존 저장은 기본 외형과 보유 철검을 보존합니다.

전체 진행 상태와 집·죽음 추적 시나리오는 [개발 목록](docs/DEVELOPMENT_ROADMAP.md)에 정리했습니다. 고정 주택 한 채의 소유·일지 보관과 사망 사건 조사를 구현했습니다. 등불지기의 목격 증언으로 NPC 사건을 조사할 수 있습니다. 건축과 상속은 후속 작업입니다.

### 인벤토리

`I` 또는 오른쪽 ‘소지품’으로 가방을 엽니다. 아이콘 격자에서 아이템을 선택하면 설명·현재 수량·보유 한도·착용 상태를 확인할 수 있습니다. 재료/소모품/장비/기록 필터와 이름순 정렬을 제공합니다. 가방에서 장비 착용/해제와 약초 사용이 가능하며, 체력이 가득 찼을 때 약초를 소비하지 않습니다. 은화는 별도 지갑으로 표시합니다.

기존 철광석·약초·철검·유물 수량을 그대로 사용하므로 저장 변환으로 아이템이 복제되지 않습니다. 시작 장비의 소유 상태는 별도로 저장됩니다. 현재는 종류별 묶음이며 무게, 드래그 이동, 버리기, 보관함 이동, 개별 장비 내구도·옵션은 후속 작업입니다. 빈 칸은 표시 공간이며 24칸 용량 제한은 아직 적용하지 않습니다. 싱글은 가방에서 정지하고 멀티는 계속 진행합니다.

### 조작과 첫 여정

WASD/방향키 이동, E 상호작용, Space 공격, Shift 회피, Q 약초 사용, J 일기, Esc 기록 닫기.

1. ‘나만의 세계 시작 / 이어하기’로 입장합니다.
2. 오른쪽 위 철광맥에서 E로 철 2개를 캡니다.
3. 마을의 붉은 지붕 대장간 가까이에서 E로 철검을 만듭니다.
4. 예배당 근처 늑대의 붉은 공격 예고를 보고 회피하며 싸웁니다.
5. 예배당을 조사하고 마을 서재에서 약초사 이렌의 기록을 읽습니다.
6. 생활 방침을 선택하고 ‘생활 맡기기’ → ‘실험 · 하루 진행’ → J로 생활 일기를 확인합니다.

싱글은 창을 닫을 때 저장하고 다음 실행 때 부재 시간을 계산합니다. 일기 열람 중 싱글 시간은 정지합니다. 멀티의 시간은 계속 흐릅니다. 하루는 현실 48분이며 실제 480일을 기다리는 대신 싱글의 실험 버튼으로 생활을 확인할 수 있습니다.

### 전용 서버 시험

Mac에서 프로젝트 루트 기준:

```sh
builds/Vestige-0.4.3.app/Contents/MacOS/Vestige --headless -- --server
```

Windows에서 실행 파일 폴더 기준:

```bat
Vestige.exe --headless -- --server
```

UDP 27180, 최대 8명 설정의 개발용 서버입니다. 게임의 공유 서버 주소란에 서버 주소를 입력합니다. 같은 컴퓨터에서는 `127.0.0.1`을 사용합니다. 클라이언트를 닫아도 서버가 실행 중이면 생활이 이어집니다. 인터넷 공개 운영용 인증·암호화·운영 도구나 Steam 친구 초대는 아직 제공하지 않습니다. 같은 OS 사용자로 실행한 클라이언트는 저장된 동일 신원을 사용하므로 동시 다중 접속을 허용하지 않습니다.

데스크톱 저장은 Godot의 `user://` 아래 `single-world.json`, `shared-world.json`, `identity.txt`에 분리됩니다. Mac의 기본 위치는 `~/Library/Application Support/Godot/app_userdata/Vestige — 잿불의 기록/`입니다. 브라우저 시제품의 저장을 자동으로 가져오지 않습니다. 저장할 때 이전 파일의 `.bak`도 생성합니다. 싱글은 재접속할 때 부재 생활과 처리 시각을 한 번에 저장합니다. 전용 서버가 멈춘 동안에는 세계 시간도 멈춥니다. 원본이 없거나 손상되면 정상 백업을 읽습니다. 원본과 백업 모두 읽을 수 없거나 원본이 더 높은 버전이면 게임 진입을 중단합니다.

### 설치형 구현 범위

원본 도트 지형·건물·캐릭터, 연속 이동, 건물 충돌, 적 추적·공격 예고·회피·치료, 채집·단조·유적 발견, 부재 중 생활·노화·일기, 사망·추모·새 인물, 파일 저장, 별도 ENet 서버와 두 클라이언트 연결을 구현했습니다.

일부 주민은 시각적 배경 인물입니다. 경지 돌파·부활·회춘·수요 기반 경제·시신 운송·주택 건축·물리적 책 아이템·일기 공개 권한·Steamworks·일반 PC 설정 화면은 아직 없습니다. 언덕집 주인의 일기는 집과 현장을 조사한 인물이 서재에서 열람할 수 있습니다. 기존 공개 일기는 유지됩니다. 단일 마을의 짧은 여정을 검증하는 시제품이며 출시 완성본은 아닙니다.

### 개발 검증

2026-11-05 Mac UI에서 이동·채굴·제작·공격과 사망·새 인물·묘지·서재 열람을 확인했습니다. 부재 방침을 약초 채집으로 설정하고 생활 맡기기 → 하루 진행을 눌렀을 때 약초가 10→12개로 증가하고 해당 사건이 일기에 기록되는 것을 확인했습니다. 체력·기력 막대 겹침을 수정했습니다. 전투 승리·유적 보상 전체 흐름의 반복 UI 검증은 후속 항목입니다.

기존 싱글 저장과 분리해 시험하려면 Mac 실행 파일에 `-- --qa`를 전달합니다. 시험 월드는 `user://qa-world.json`에 저장되며 일반 실행은 기존 `single-world.json`을 사용합니다.


```sh
.tools/godot/Godot.app/Contents/MacOS/Godot --headless --path desktop --script tests/test_world.gd
```

외형·장비·기존 저장 호환·새 인물 생성 UI 검사는 `desktop/tests/test_customization.gd`에서 12개가 통과했습니다. 두 클라이언트의 외형·장비·이동 동기화도 확인했습니다.

9개 규칙 검증: 수명 계산, 제작 자원 소비, 비접속 생활·일기, 사망·기록 보존, 사후 생산 중단, 새 인물, 저장 복원, 공격 예고, 회피. ENet 서버에 서로 다른 신원의 테스트 클라이언트 2개를 연결하는 `desktop/tests/network_client.gd`도 포함했습니다. 테스트 서버는 `--world-file=/tmp/vestige-network-world.json` 옵션으로 실제 공유 저장과 분리했습니다.

내보내기는 `desktop/export_presets.cfg`를 사용합니다. Mac 템플릿 경로는 이 작업 폴더의 절대 경로이므로 프로젝트를 옮길 경우 경로를 수정해야 합니다. 엔진·템플릿은 `.tools/`, 빌드 결과는 `builds/`에 두며 버전 관리 대상에서 제외합니다.

Mac 내보내기 뒤 `python3 scripts/finalize_macos.py builds/Vestige-0.4.3.app`을 실행합니다. 실행 파일과 PCK의 이름만 ASCII로 정규화하고 ad-hoc 서명 및 검증을 수행합니다. 화면의 한국어 제목은 유지됩니다. 최신 빌드는 이 처리를 마쳐 서명 검증을 통과했습니다.

## 최종 목표

Steam에 출시하는 설치형 PC 다크판타지 RPG입니다. 시각 스타일은 **2D 탑다운 도트(픽셀 아트)**로 확정했습니다. 독립된 싱글 월드와 실시간 멀티 월드를 제공하며, 우선 Windows를 대상으로 계획합니다. 다른 OS와 Steam Deck 지원은 추후 검증합니다.

기존 브라우저 버전은 규칙 검증용 시제품으로 보존했습니다. 아래 Node.js 실행 방법은 브라우저 시험에만 필요합니다. 설치형 앱은 Node.js를 요구하지 않습니다. Steamworks 연동은 아직 없습니다.

설치형 시제품은 코드로 그린 원본 픽셀 지형·건물·인물을 사용합니다. 최종 에셋은 공통 픽셀 규격의 타일·캐릭터·장비·애니메이션으로 제작하고, 일기와 한글 UI는 별도로 가독성을 확보합니다.

설치형 엔진은 Godot로 선정하고 최소 빌드와 전용 서버 연결을 검증했습니다. 싱글은 로컬 저장과 부재 시간 계산을, 멀티는 실행 중인 서버의 지속 처리를 사용합니다. 자세한 출시 기준과 단계는 [기획서](docs/GAME_DESIGN.md)에 기록했습니다.

## 이전 브라우저 시제품 실행

Node.js 22 이상에서 외부 패키지 설치 없이 실행합니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. 테스트는 `npm test`입니다. 서버는 로컬 인터페이스에만 연결하며 공개 서비스용 인증은 포함하지 않습니다.

## 첫 여정

1. 이름을 정하고 싱글 월드에 입장합니다.
2. WASD 또는 방향키로 동쪽 광맥에 이동하고 E로 철 2개를 캡니다.
3. 서쪽 대장간에서 E로 철검을 만듭니다.
4. 예배당 앞 늑대 가까이에서 Space로 공격하고 예배당을 조사합니다.
5. 마을로 돌아와 생활 방침을 정하고 생활 맡기기를 누릅니다.
6. 싱글 실험의 하루 진행을 눌러 비접속 활동과 일기를 확인합니다.

공유 월드 시험은 일반 브라우저와 시크릿 창에서 각각 공유 세계로 입장합니다. 동일 브라우저 저장소는 같은 신원으로 취급합니다. 각 클라이언트는 2초 간격으로 상태를 갱신합니다. 싱글 월드는 서버가 신원별로 분리합니다.

저장은 `data/worlds.json`에 기록됩니다. 브라우저 신원 토큰은 localStorage에 저장되므로 삭제하면 기존 인물에 접근할 수 없습니다. 서버 재시작 시 마지막 저장부터 경과 시간을 적용합니다. 서버 운영 중 연결이 15초 이상 없으면 생활 상태로 전환합니다.

## 구현 범위와 제한

- 타일 이동, 자원 채집, 철검 제작, 공격과 반격, 치유, 유적 발견.
- 독립 싱글/공유 월드, 서버 검증, 원자적 파일 교체 저장.
- 하루 단위 비접속 생업·수련·채집·휴식과 사실 기반 일기.
- 전투/노환 사망, 추모 기록, 사망자의 공개 일기와 새 인물.
- 이번 버전의 모든 사망 일기는 공개 시험 자료입니다. 개인 공개 권한 UI는 아직 없습니다.
- 마을 외부에서 명시적 생활 맡기기는 제한합니다. 연결 끊김 후에는 장소와 무관하게 추상화된 생활 처리가 진행됩니다. 안전 귀환 AI는 미구현입니다.
- 늑대는 플레이어 공격에 반격하는 정적인 적입니다. 추적 AI, 방어·회피, 쓰러짐·구조, 시신 운송은 미구현입니다.
- 일기는 사망 시 공개 서재 자료로 보존됩니다. 물리적인 책 아이템·필사·상속은 미구현입니다.
- 수명 계산은 포함하지만 경지 돌파, 부활, 회춘, 거래·수요 경제는 미구현입니다.
- 엔진 선택 전 게임 규칙과 흐름을 검증하는 브라우저 시제품입니다. 실시간 전용 게임 엔진 수준의 동기화나 대규모 운영을 제공하지 않습니다.
