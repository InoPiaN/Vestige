## 바로 다음 구현 단위 제안
01-A: G 기반 별도 통합 브랜치에서 S의 증거/대화 규칙을 고유 모듈 이름으로 옮기고 테스트를 보존한다. 신규 챕터 진실/증거/콘텐츠는 추가하지 않는다.
01-B: room/location 검증, 새 삶 초기화, E/N와 모달, 서버 dialogue/reconstruct 경로 연결.
01-C: 승인된 저장 계약으로 v1 story/v23 gameplay 복사 fixture 이관, 손상/미래 버전/백업 실패·비공개 정보 보호 검증.
01-D: 이번 확인된 S의 ENet 송신 오류를 최소 재현·수정·회귀 검증하고, 실제 두 클라이언트가 I03/I04/I07을 각각 조합하고 재접속/서버 재시작 후 보존하는 E2E, 기존 생활·전투 회귀, Mac 실제 플레이. Windows 실기 검증을 별도 추적한다.

현재 위치 복구 스태시는 먼저 보존·영향 분석한다. 정상 통합을 막는 이동/충돌 결함은01에서 최소 수정하되, 광범위한 조작감/카메라 개선은03으로 유지한다. 데이터 계약을 문서로 제안하는 이번 작업은02 구현 착수가 아니다.

## 단계 공통 완료 조건
- 요구사항 ID/승인된 설계 revision과 변경 commit 기록.
- 미커밋 변경/스태시 보존, main 직접 수정 금지, purpose별 브랜치.
- 변경 코드 파싱·관련 자동 검사·기존 기능 회귀. 자동 UI 객체 검사와 실제 플레이를 구분.
- 싱글/멀티 권한·죽음/새 생애·저장/재접속의 영향 확인.
- 미실행/실패/검사 한계와 남은 항목을 명시.
- 기능 코드가 없는 설계는 planned/specified로 유지. 테스트를 보유하기만 한 기능을 verified로 표시하지 않음.
- 신규 게임 기능은 기존 요청대로 참고 게임 조사·적용안 승인 후 구현. 현재 통합 감사에는 신규 게임 규칙을 도입하지 않는다.
