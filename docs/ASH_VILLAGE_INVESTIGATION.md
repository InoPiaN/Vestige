# 제1장 《마지막 약속》 현장 조사 프로토타입

기준: `feature/ash-village-dialogue-prototype`의 `7c99f8f`.
작업 브랜치: `feature/ash-village-investigation`. 날짜: 2026-11-21.
기획 참조: `origin/docs/vestige-story-concept-v0-3`의 `b296969addb6eece2b8477a04cf3e980de8197a4`, `docs/STORY_CONCEPT.md` 6절. 해당 문서는 별도 브랜치에서 읽었으며 병합하지 않았다.

## 기존 구조 분석과 변경 영향

- `main.gd`: E 입력은 NPC를 우선하고 시설로 이어지며, 대화는 `command` RPC와 서버의 일시적인 대화 세션을 사용한다. 조사도 같은 명령 경로로 연결했다. NPC → 조사 지점 → 기존 시설 순서이며 두 조사 지점은 기존 NPC/시설의 주 상호작용 위치와 겹치지 않는다.
- `world.gd`: `people[id]`를 version 1 JSON에 저장하며 `outfit`이 기존 데이터의 기본값을 채운다. 이 경로에 조사 상태 초기화와 JSON 숫자 타입 복원을 추가했다. 기존 채집·단조·전투·유물 보상 규칙은 그대로다.
- `dialogue.gd`: 최초/재방문/소문 분기를 유지하고, 획득한 증거에 따라 ‘발견한 증거에 관해 묻는다’ 선택지를 추가했다. 증거가 없는 요청은 서버에서 거절한다.
- `investigation.gd`: 증거 정의, 거리·생존·직접 조종·늑대 조건 검사, 중복 방지, 수첩 표시와 증거 대사 분기를 담당한다. `world.gd`에 역참조하지 않는다.
- 멀티 스냅샷은 이미 타인의 `story`를 제외한다. 증거도 이 안에 저장하므로 다른 살아 있는 플레이어의 개인 수첩은 전송되지 않는다. 클라이언트는 증거 ID만 요청하고, 본문·출처·순서·시각은 서버가 결정한다.
- 서버는 조사 처리 직후 저장한다. 기존 서버의 주기 저장/연결 해제 저장도 유지한다. 연결 종료 중인 ENet 상대에게 스냅샷을 보내지 않도록 상태 검사를 추가했다.
- 일지·서재의 기존 공용 패널을 조사 수첩에 재사용한다. 수첩을 연 채 새 스냅샷이 도착하면 내용을 갱신한다. 싱글 패널 열기는 기존처럼 시간을 멈추며, 공유 서버 시간은 계속 흐른다.

## 플레이 방법과 범위

1. 마을 북동쪽 **이렌의 집** `(16, 6)` 앞 `(16, 7)`에서 E: **마지막 약속 일기**를 기록한다.
2. 늑대를 처치하고 예배당 남쪽 석판 `(27, 12)`에서 E: **예배당 현장 흔적**을 기록한다.
3. **N** 또는 ‘N · 조사 수첩’ 버튼: 출처, 발견 순서와 시각, 확인된 사실, 추정을 읽는다. ESC로 닫는다. J 일기에도 발견 기록이 남는다.
4. 브란/세라와 대화해 증거 선택지를 고른다. 일기만/흔적만/둘 다 보유한 상태에 각각 다른 대사가 나온다.

조사 반경은 **1.125 타일 미만**이다. 두 증거의 선행 순서나 소문 청취 조건은 없다. 흔적부터 수집해도 집 일기를 나중에 얻을 수 있다. NPC 대화는 증거를 소모하지 않는다.

집은 기존 건물 도형과 충돌을 재사용한 **입구 책장 조사 방식**이다. 별도 실내 맵·출입 장면은 이번 범위에 포함하지 않았다. 기존 예배당 유물 E 지점 `(27, 9)`과 현장 지점은 분리되어 있다. 유물 획득 여부는 증거 수집을 막지 않으며, 조사만으로 유물이나 장비를 지급하지 않는다. 늑대가 부활하면 아직 기록하지 않은 현장 조사는 다시 처치해야 하지만 이미 얻은 증거는 수첩에 남는다.

일기에 약속 문구가 있다는 관찰과 실제 만남이 있었다는 추정을 구분한다. 석판 손상·흙의 눌린 흔적도 원인과 시점을 단정하지 않는다. 카엘, 사고 원인, 사망 경위, 범인, 봉인 장치 작동 등 미확정 진실은 구현하지 않았다. 이 텍스트들은 첫 조사 프로토타입의 관찰 자료이며 전체 사건의 확정 결론이 아니다.

## 저장 구조와 생애

```text
people[player_id].story.evidence[evidence_id] = {
  id, title, source,
  order,          # 인물별 1부터 시작하는 발견 순서
  discovered_at,  # 서버/싱글 월드의 경과 초, 실제 달력 시각 아님
  day,            # 발견 당시 월드 날짜
  fact,           # 직접 확인한 문구/관찰
  inference       # 추정·미확인 해석
}
```

ID는 `last_promise`, `chapel_traces`다. ID별 딕셔너리이므로 재조사로 증거·일지 항목이 중복되거나 최초 발견 시각/순서가 바뀌지 않는다. 취득 당시의 출처와 본문을 저장한다.

기존 version 1 저장에서 `story` 또는 `evidence`가 없으면 빈 목록을 보충한다. 기존 소문·방문 이력·외형·아이템·유물은 보존한다. 과거에 유물을 얻었다는 사실만으로 새 증거를 소급 지급하거나 발견 시각을 만들어 내지 않는다. JSON 로드 시 순서와 날짜는 정수, 경과 시각은 실수로 복원한다.

발견 내용은 기존 `events` → 하루 종료 시 `journal` 흐름을 따른다. 사망 시 기존 책에 남은 일기가 보존되며, 새 인물의 수첩은 빈 상태다. 이전 인물의 기록을 읽더라도 새 인물의 증거 플래그는 자동으로 바뀌지 않는다. 사망자의 책 공개는 기존 게임 규칙을 유지한다.

Godot **4.5.1** 사용. 사용자 세이브 대신 `/tmp`와 임시 디렉터리를 사용했다.

```sh

# 아래 각 이름을 res://tests/<이름>.gd로 실행

.tools/godot/Godot.app/Contents/MacOS/Godot --headless --path desktop --script res://tests/test_investigation_ui.gd

```

### 검사 중 발견하고 수정한 사항

- 제한 환경에서 Godot 사용자 로그 접근 실패와 엔진 종료가 발생해 승인된 권한으로 재실행했다.
- JSON 저장 전후 숫자 타입 차이로 증거 딕셔너리 비교가 실패해 로드 타입 정규화를 추가했다.
- 연결 종료 신호보다 먼저 ENet 전송 채널이 닫히는 경우가 있어 스냅샷 전송 전에 연결 상태를 확인한다.
- 긴 통합 테스트 중 로그아웃 주민이 여관으로 이동했다. 재접속 검사는 저장 위치가 NPC 옆이라고 가정하지 않고 NPC에게 다시 접근한다.

## 미검증 및 후속 범위

- 실제 GUI 수동 플레이, 한글 글꼴·가독성·창 크기별 배치, OS 키보드/마우스 입력은 미검증이다. PNG를 생성하거나 스크린샷을 만들지 않았다.
- Windows 빌드/실행, 실제 외부망 지연·패킷 손실·강제 단절 복원력, 장시간 다중 접속 부하 검사는 미실시다.
- 기존 저장 함수의 I/O 실패 통지·손상 파일 복구, 계정 인증 강화는 별도 과제다.
- 집 내부 탐험, 추가 증인·현장 오브젝트, 물리 증거 아이템·거래, 카엘 대면, 사건 결론과 공개/보존 선택은 후속 범위다.
- PNG/이미지 API/OpenAI API/유료 기능 호출 없이 기존 임시 그래픽만 사용했다. 원격 푸시는 하지 않는다.
